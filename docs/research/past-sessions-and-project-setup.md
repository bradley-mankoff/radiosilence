## What "projectified" means here, and what is missing

The Factory spec (`~/Developer/personal_code/factory/2026-10-16-factory-stack.md`) says: "The Human gives an Idea in a few plain sentences. The Factory turns it into reviewed, merged code in the right project repo." A project is one repo led by one Project Manager ("the agent that leads one project. It runs as a pi session in that project's herdr pane"), working through grilling (interview the Human until one shared understanding exists), `to-spec` (the Spec is stored as the description of an Epic, "so specs do not pile up as documents"), and `to-beads` (the Epic's Beads, each "a thin vertical slice that can be shown working on its own"). The glossary (`~/Developer/personal_code/factory/GLOSSARY.md`) confirms: "Spec: the written, domain-modelled version of an Idea, in the project's own words. A Spec is stored as the description of an Epic, not as a file in the project repo"; "Map: an Epic labelled `wayfinder:map`"; "Project Manager: the agent that leads one project." Setup per project is `scripts/install.sh` given the repo, which writes `.archon/.env`, trusts the repo, and lists it in FactoryClaw's `TOOLS.md`, with the repo line also present in `~/.config/factory/projects`.

Against that bar, Bad Game Warning has Beads (`bd init` done, memories working), `AGENTS.md`, `CLAUDE.md`, and git, but it is missing: a `GLOSSARY.md`, any Epic or Map in Beads (only two closed tasks exist), a Wayfinder map for the five future epics, the HTML handoff the Boss asked for, registration in `~/.config/factory/projects` (which today lists only `factory-toy-calc`, `factory-toy-todo`, and `socratic-dialogue-facilitator`), and a herdr pane.

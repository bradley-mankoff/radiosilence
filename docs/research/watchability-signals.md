# Watchability signals research

Date: 2026-10-25. Context: Bad Game Warning (app.py, README.md) is a single-file Python server that fetches ESPN's public NBA summary endpoint and shows one spoiler-free verdict for tonight's Dallas Mavericks game. Today the only signal is opponent win probability above 95 percent from 6:00 left in Q2 onward (STAY_AWAY_ODDS = 0.95 in app.py), evaluated on the latest reading so the verdict can flip back to Watch. This note answers four questions: published excitement metrics, existing spoil-free products, ESPN endpoint fields, and personal criteria detectability.

## Short answer (five sentences)

Published excitement research gives us three reusable live formulas: total win-probability movement (the Burke/inpredictable Game Excitement Index family), Ely-style suspense as the expected variance of the next belief and surprise as the size of each belief update, and baseball-style leverage for weighting plays by how much they can swing the outcome. Existing open-source projects cluster into pre-game forecast dashboards (notably cameronntaylor/nba-watchability, which scores Team Quality times Closeness through a CES utility) and spoiler-hiding highlight or score apps (stealth-score, highlight-oasis, blurred-app), and none of them does a live spoiler-free basketball watchability verdict, so this app fills a real gap. ESPN's public NBA summary endpoint for event 401909858 (fetched with curl, 437,146 bytes) carries everything needed: a 491-play play-by-play, 491 win-probability readings, per-player boxscore, leaders, videos, recap article, betting lines, injuries, standings, and season-series state. Its winprobability and plays arrays are not strictly chronological (9 order inversions and 5 wallclock inversions in this game), tiePercentage is always 0.0 in the NBA, and live boxscore, leaders, video titles, and the recap all spoil, so only win-probability-derived numbers plus pre-game context are safe to expose. Personal criteria split cleanly: overtime, dunk counts, buzzer-beaters, comebacks, rivalry, and playoff stakes are all detectable server-side, while star milestones and rookie breakouts are detectable but leak hints of the outcome, so the owner must decide how much of a positive hint is acceptable.

## 1. Published excitement and watchability metrics

### 1.1 Game Excitement Index (Burke / inpredictable)

Brian Burke's Game Excitement Index, published on Advanced Football Analytics in January 2012 (https://archive.advancedfootballanalytics.com/2012/01/game-excitement-index.html), defines excitement as the sum over every play of the absolute change in win probability: GEI = sum |WP(after play) - WP(before play)|. Evidence: the formula is restated in full in the open-source project Biggels/nfl-excitement-index (https://github.com/Biggels/nfl-excitement-index), whose README plan reads "for each game, add up the absolute value of all win probability changes on each play" and then experiments with normalizing by average plays per game, averaging changes over minutes, and weighting later changes more (retrieved via `gh api repos/Biggels/nfl-excitement-index/readme`, full text captured 2026-10-25). The live reference implementation is inpredictable.com (https://inpredictable.com/), which ranks ongoing NFL games by excitement from the same win-probability stream. Caveat: direct curl fetches of both the Burke page and the inpredictable excitement doc page returned empty bodies on 2026-10-25 (likely bot protection), and the Wayback Machine reports no capture of the inpredictable doc URL, so the exact normalization inpredictable uses (per-minute vs per-play) is listed under unknowns below.

Applied to our data, total win-probability movement for Mavericks vs Spurs event 401909858 is 6.806 over 491 readings (mean step 0.0139, home WP range 0.000 to 0.420), computed with curl-fetched JSON and a Python one-liner on 2026-10-25. A blowout still accumulates movement from early back-and-forth, which is why Burke-style indices usually pair the total with closeness weighting or a late-game window, and why the current app's late cutoff (Q2 6:00 onward) is directionally consistent with the literature.

### 1.2 Leverage index and win probability added

Leverage Index (LI) comes from baseball (Tom Tango's formulation, documented at https://library.fangraphs.com/misc/wpa/): LI measures how much the win probability could swing at a given moment relative to average, with average plays defined as LI 1.0, so high-leverage plays are the tense ones. Evidence: the FanGraphs library page attribution confirms TangoTiger licensing of Win Expectancy and Leverage Index data (curl 2026-10-25 returned the attribution page), and Wikipedia's Win Probability Added article (https://en.wikipedia.org/wiki/Win_probability_added, fetched 2026-10-25) defines WPA as crediting each player with the signed change in win probability their play caused. For basketball, the adaptation is straightforward: weight each play's |delta WP| by game time remaining so that identical swings count more in Q4, or define moment-to-moment leverage as the spread between the best and worst reachable WP after the play. Direct curl of https://www.tangotiger.net/leverage.html returned 404 on 2026-10-25, so the canonical formula page moves to unknowns, but the concept (variance-weighted importance) is well attested.

### 1.3 Suspense and surprise (Ely, Frankel and Kamenica, JPE 2015)

Jeff Ely, Alexander Frankel, and Emir Kamenica, "Suspense and Surprise" (Journal of Political Economy 2015, https://doi.org/10.1086/682893), model entertainment utility from information flow with two definitions. Evidence: Ely's own summary page (https://jeffely.com/suspense-and-surprise/, curl 2026-10-25, full text captured) states "a period has more suspense if the variance of the next period's beliefs is greater" and "a period has more surprise if the current belief is further from the last period's belief", applied to sports among other domains. Operationalized for this app: surprise over a span is exactly the Burke sum (sum of |belief updates|), while suspense at minute t is the expected variance of WP over the next few plays, which in practice is high when WP sits near 50 percent late with many possessions left and low when WP pins near 0 or 100 percent. This gives a principled two-number summary (how startling the game has been, how on-edge it should feel right now) instead of one threshold. Caveat: the journal page itself is behind a JavaScript challenge (curl returned a Cloudflare-style interstitial), so the formal variance expressions are cited from the authors summary rather than the paper text.

### 1.4 Supporting signals used elsewhere

Lead changes, ties, and comeback size recur across every system surveyed. In event 401909858 there were 10 lead changes and 8 returns to tied, all early, with zero crossings of 50 percent win probability and a final margin of 122 to 106 for San Antonio (home-away margin ranged from plus 6 to minus 23), which is the quantitative signature of the "close first quarter, decided by halftime" game the current rule handles well. Comeback factor is the maximum deficit the eventual winner overcame (here about 6 points by San Antonio, small). The soccer excitement index in jkbren/excitement-index-soccer (https://github.com/jkbren/excitement-index-soccer, found via `gh search repos "excitement index"`) rates matches 0 to 10 from StatsBomb event data for the NetSI/Northeastern World Cup project, which is evidence that event-type counting (shots, cards) complements probability flow. FiveThirtyEight's March Madness excitement index (consumed by mlm603/MMEAT, https://github.com/mlm603/MMEAT: "scrapes FiveThirtyEight for Excitement Index") is the closest mainstream precedent for a single excitement number per game, though its formula is proprietary.

## 2. Existing worth-watching and spoiler-free products

### 2.1 Pre-game watchability forecasters (closest in spirit)

cameronntaylor/nba-watchability (https://github.com/cameronntaylor/nba-watchability, live at https://nba-watchability.streamlit.app/, announced via https://x.com/NBAWhatToWatch) is the most directly relevant system found. Evidence from `gh api` file reads on 2026-10-25: core/watchability.py scores Team Quality as (average win pct minus floor) normalized to [0,1] with WIN_MIN 0.2 and WIN_MAX 0.7, scores Closeness from the betting spread as ((15 minus spread)/(15 minus 0.5))^0.9, and combines them through a CES utility with SIGMA 0.4 and quality weight 0.7, scaled to a 0 to 100 Watchability Index labeled Must Watch (90+), Strong Watch (75+), Watchable (50+), Skippable (25+), Hard Skip (below 25). Star power enters as a small additive win-pct bump (STAR_WINPCT_BUMP 0.075 from points, rebounds, assists, steals, blocks in core/watchability_v2_params.py), injuries enter through availability weights (Out 1.0 down to Available 0.0) and impact shares, and pre-game spreads come from The Odds API with ESPN smoothing over the first ten games (README season-transition strategy). This is a pre-game product (which game to plan around), not a live spoiler-free verdict, so it complements rather than duplicates Bad Game Warning. Related: nihalraman/nba-watchability-index (Docker web app with a /data/ API, sparse README, `gh repo view`), and dirkstahlecker/nhl-should-i-watch (hockey equivalent in name only; its README is an unmodified TypeScript template, verified via `gh api`).

### 2.2 Spoiler-hiding sports apps (closest in UX)

`gh search repos "spoiler free sports"` on 2026-10-25 returned an active cluster. rufusccortina/stealth-score calls itself a "spoiler-free sports results platform" where results stay hidden until the user reveals them, including a "reveal event by event" mode (README via `gh api`); it covers soccer through api-sports.io with an Express backend and no frontend yet. joshua-z-zheng/highlight-oasis is a "spoiler-free sports highlights tracker" joining football-data.org fixtures to YouTube highlights, with NBA and NFL listed as planned features (README via `gh api`). JulOuellet/blurred-app is "a spoiler-free sports highlights browsing web app" in Go with templ (README via `gh api`). keifererikson/darkmodesports is "a spoiler-free sports schedule web app" and shaztechio/score-shield generates metadata tracks so titles update with live scores without spoiling. None combines a live computed verdict with a strict no-score page the way this app does.

### 2.3 Threshold alerting precedent

mlm603/MMEAT (March Madness Excitement Alerting Tool) tweets at @MMEATool when a game's excitement index exceeds a threshold, explicitly "intended to engage casual/non-basketball viewers who might only want to watch the most interesting games" (README via `gh api`). That is the exact interaction model a richer Bad Game Warning could grow into (a Watch ping when a game crosses into must-see territory), except this app inverts it into Stay away detection for watching from behind. `gh search repos "should I watch"` otherwise returned only movie recommenders (koffeinfrei/should-i-watch-this uses Rotten Tomatoes/Metacritic/IMDB), confirming no established basketball equivalent.

## 3. ESPN public NBA summary endpoint fields

### 3.1 Fetch and top-level shape

Fetched with `curl -s https://site.api.espn.com/apis/site/v2/sports/basketball/nba/summary?event=401909858` on 2026-10-25: 437,146 bytes of JSON with top-level keys boxscore, format, gameInfo, leaders, seasonseries, injuries, broadcasts, pickcenter, odds, againstTheSpread, news, plays, header, winprobability, article, videos, wallclockAvailable, meta, standings. Game 401909858 is San Antonio at Dallas, final 122 to 106, status post (header.competitions[0].status: Final). app.py uses only summary.header (home/away), summary.plays (period, clock), and summary.winprobability (homeWinPercentage), plus the schedule endpoint for dates.

### 3.2 Plays (491 entries, the narrative stream)

Each play carries id, sequenceNumber, type (for example "Running Dunk Shot", "Shooting Foul", "End Period", "Coach's Challenge (Overturned)"), text ("Stephon Castle makes running dunk (Devin Vassell assists)"), awayScore and homeScore after the play, period number and display value, clock displayValue ("12:00" down to "45.2"/"0.0" styles, parsed by seconds_left in app.py), scoringPlay boolean, scoreValue, team id, participants (athlete ids), wallclock timestamp, shootingPlay, coordinates, and shortDescription. The stream supports every event-count signal in section 4 (dunks, blocks, and-ones, buzzer attempts, quarter boundaries, substitutions, timeouts, challenges). Score and clock fields spoil by nature and must never leave the server, consistent with the existing project memory that the page sends no score, clock, quarter, or percentage.

### 3.3 Winprobability (491 entries, the tension stream)

Each reading carries homeWinPercentage, tiePercentage, and playId joining to plays. All 491 playIds match all 491 play ids exactly, so coverage is complete for this game. tiePercentage is 0.0 on every single reading (1 distinct value across 491), which is expected because NBA games cannot tie; the field exists for sports with ties (notably the NFL) and can be ignored for basketball. The home (Dallas) win probability ranged from 0.000 to 0.420 and never crossed 50 percent, matching the away blowout.

The two arrays are not strictly chronological, as the task suspected. Measured on 2026-10-25: 9 inversions where winprobability order disagrees with plays array order (for example winprobability index 95 points at plays index 98 while index 96 points back at plays index 95), and 5 wallclock inversions inside plays (for example play 401909858215 free throw at 00:46:19 followed by substitution 401909858218 stamped 00:45:57). The pattern is that corrections (substitutions, timeouts, coach's challenges such as "COACH'S CHALLENGE (Overturned)" at 8:24 Q2) get inserted with earlier timestamps than surrounding scoring plays. Consequence for app.py: verdict() takes readings[-1] in winprobability array order and joins to plays by id, which happened to be the true final play here ("End of Game") but is not guaranteed; sorting joined readings by sequenceNumber (with wallclock as a tiebreak) before taking the latest would make the rule robust. test_app.py builds synthetic summaries where ids already sort, so it cannot catch this.

### 3.4 Article and videos (the story stream, post-game and spoiling)

article is an AP recap (id 50273162, published 2026-10-25T02:49:45Z, about two hours after tip): headline "Wembanyama, Harper lead Spurs past short-handed Mavericks 122-106 for their first victory", description with the score, and a story body naming stars, the rookie (Sergio de Larrea, 21 off the bench), missing marquee players (Cooper Flagg shoulder injury, Kyrie Irving out), and losing streaks avoided. Every field here spoils and it appears only after the game, so its role is retrospective labeling (was this game a story worth knowing about) or next-morning justification, never a live signal. videos holds 4 highlight clips (15 to 18 seconds each, embargo timestamps included) with headlines like "Stephon Castle throws down powerful slam dunk vs. Dallas Mavericks" and "Julian Champagnie gets up for the beautiful flush"; clip count by category is computable, but titles name players and plays, so they spoil. news is league-wide rather than game-specific (this fetch led with Warriors vs Suns highlights), so it is not a per-game signal.

### 3.5 Boxscore and leaders (the star stream, live but spoiling)

boxscore.teams has full team tables (example Dallas: FG 45-88, 3PT 11-28) and boxscore.players has per-athlete rows with MIN, PTS, FG, 3PT, FT, REB, AST, TO, STL, BLK, OREB, DREB, PF, plus-minus (example Victor Wembanyama: 29 minutes, 23 points, 9-18 FG, 7 rebounds, 4 blocks, plus 32). leaders distills the same into per-team category leaders (example Dallas points leader Sergio de Larrea with 21). Both update live and both spoil through totals, so the spoiler-free pattern is to compute threshold flags server-side (30-point game, triple-double watch, 7+ blocks, career-high proximity) and expose only the flag, never the number. Whether even the flag is acceptable (it hints someone went off) is an owner decision recorded in section 5.

### 3.6 Pre-game context (safe to show any time)

pickcenter carries the betting market (here DraftKings: SA minus 14.5, over/under 229.5, Spurs moneyline minus 900, Mavericks plus 600), which is the standard expected-closeness input and is fully spoiler-free before tip. odds was an empty array in this fetch while againstTheSpread held team trend records. injuries lists statuses with dates (here Kyrie Irving Out, plus Flagg news inside the recap), which feeds both the star-availability downgrade and the rookie-opportunity upgrade. standings holds the full league table (2026-27, wins, losses, streak like W3), seasonseries holds the matchup state ("SA leads series 1-0" of 4), broadcasts lists outlets (MavsTV, DAZN SAS), and gameInfo holds venue, attendance (19,555), and officials. schedule events (used by todays_game/next_game) add date, state (pre/in/post), and home/away. None of these reveal anything about tonight's score before tip.

## 4. Personal criteria: what is detectable without spoiling

Criteria are grouped by whether the server can compute them from the endpoint and whether exposing them preserves the page's spoiler-free guarantee (server sends no score, clock, quarter, or percentage, per project memory).

Detectable live and safe to expose as bare flags or counts: overtime (period number above 4 in plays, or status detail containing OT; this game had periods 1-4 only), since a bare "went to overtime" flag reveals drama but not the winner. Dunk and block counts (18 dunk plays here matched by "dunk" in play text across types "Running Dunk Shot", "Cutting Dunk Shot", "Alley Oop Dunk Shot", "Driving Dunk Shot"; blocks such as "Risacher blocks Wembanyama's 2-foot dunk"), exposed as buckets ("dunk-fest") rather than timestamps. Comeback and tension from the win-probability stream alone: range, 50-percent crossings (0 here), time spent below 5 percent, largest deficit erased, and Ely-style cumulative surprise (6.806 here, front-loaded). Rivalry (static mapping of opponent id plus seasonseries state, e.g. "SA leads season 1-0") and playoff stakes (standings win pct, games behind, streak, plus games remaining from the schedule) are fully pre-game and spoiler-free; pickcenter spread (minus 14.5 here) sets the expectation baseline so an upset reads as a story.

Detectable but inherently hinting: star milestones (Wembanyama 23/7/4 blocks, Castle 19, Fox 19 from boxscore/leaders) since naming a 40-point scorer implies a big night even without the score; triple-double and career-high watches need a small preseason stat baseline the app does not currently store. Rookie breakouts (de Larrea's 21 off the bench, Harper's 22) are visible in boxscore athlete ids but rookie status itself is not in the endpoint, so the app needs an owner-kept rookie watch list matched by athlete id (injuries and recap text confirm status only after the fact). Buzzer-beaters are detectable (scoringPlay at clock 0.0 adjacent to an End Period play; this game had only a missed heave at 0.0 in Q1, play 401909858186) but a live "buzzer-beater" flag is maximally spoiling at the exact moment it matters, so it fits a post-game label better than a live one. Missing stars cut the other way and are safe: Irving Out plus Flagg's shoulder (injuries plus recap) is pre-game context that lowers expectations without revealing anything.

Not detectable from this endpoint: ejections beyond play text, fights and crowd moments, referee controversy beyond foul counts, broadcast quality, career-record ceremonies, load-management surprises before the injury report updates, and anything about games other than the final score in news (which is league-wide). Video clip titles and the recap confirm story beats (dunks, dagger threes, streaks snapped) but only after publication and always with the score attached.

## 5. What is still unknown

The exact normalization inpredictable applies to its Game Excitement Index (per-play average vs per-minute vs late-weighting) could not be confirmed because both the Burke original page and the inpredictable doc page returned empty bodies to curl on 2026-10-25, and the Wayback Machine holds no capture of the doc URL. Whether ESPN's summary endpoint serves videos, article, and pickcenter during live games (versus post-game only) needs a live-game fetch, since event 401909858 was already final when pulled. The canonical play ordering (sequenceNumber versus wallclock versus array order) needs confirmation from a second game, ideally one with a coach's challenge or stat correction near the final minute. FiveThirtyEight's March Madness excitement formula is proprietary, so MMEAT only proves the alerting pattern, not the math. Which positive flags the owner considers acceptable spoilers (a "triple-double watch" or "overtime" banner inherently reveals the game is close) is a product decision, not a data question. Open threads for later: per-play WP update cadence below one minute (clock shows tenths like "45.2" and "0.7"), women's and international tiePercentage behavior, and whether leaders/boxscore update in real time or on a delay during live games.
